# Clinical release prerequisites

This repository implements a development research preview, not a clinically validated patient service. Automated source checks establish identity, version, access, literal extraction and some numeric fidelity. They do not establish evidence certainty, communication completeness, clinical appropriateness, or personal applicability.

## Accountable roles

The project owner is responsible for appointing a qualified adult-diabetes clinician, a qualified English/Indonesian medical-language reviewer, and an operational owner before any patient release. The owner must arrange source-rights and Indonesia-specific privacy/classification review. The automated agent is not a clinical reviewer and has supplied no approval records.

## Required records

The controlled server-side data/evidence/review.json is empty by default. Never accept approvals from API clients or an LLM. For each source approval, record:

- record_hash: the value generated by python -m src.ingest, binding source identifiers, passages, study facts, limitations and content version.
- reviewer: accountable reviewer identity.
- approved_at and expires_at: timezone-aware ISO timestamps; future, missing or expired approval dates cannot enable publication.
- resolved_issues: an explicit acknowledgement/resolution for every listed corpus review blocker.

Corrections need a separate reviewed record bound to SHA-256 of the exact sorted JSON commentCorrection array returned by the metadata provider. A source approval alone cannot dismiss a correction.

Translations need a reviewed record_hash calculated from source record_hash concatenated with the exact proposed Indonesian text. Changing either source or wording invalidates approval. Each translated medical string needs review of qualifiers, units, numbers, population, negation and uncertainty. The initial corpus has no approved Indonesian medical translations.

The safety approval uses the SHA-256 policy hash reported by src.safety.policy_hash(), binding both the routing criteria and every fixed localized message. Approved safety guidance and local contact availability must be reviewed and periodically checked. Keyword guards are not validated emergency detectors; absent matches never imply safety.

The implementation enforces these record/version gates, but a JSON record is not independent proof of a clinician's qualification or completed clinical validation. Access to the review manifest and deployment configuration must be restricted and audited by the operator.

## Evaluation before patient release

Recommended release assessment: at least 200 held-out English and 200 held-out Indonesian questions adjudicated by qualified reviewers, including unsupported topics, null/conflicting findings, subgroup mismatch, old/corrected/retracted sources, provider failures, misleading omissions and out-of-scope personal requests. Keep development and release questions separate.

Require all displayed medical claims to have inspectable support, no observed erroneous study values/units/denominators, no invented citations, no unauthorized personalized treatment and no unchecked safety content in the release set. Report uncertainty and sample size; zero observed errors in this sample is not zero population risk. Measure unsupported answers, incorrect refusals, patient comprehension, source-update latency, p95 response time and cost. The owner and clinician must explicitly accept residual risk; automated tests do not replace this assessment.

## Operational prerequisites

- HTTPS with a real authentication/abuse-control perimeter for internet hosting; no shared secret embedded in clients.
- Named data controller/processors, retention/deletion policy, consent, hosting/cross-border analysis, and Indonesia intended-use classification.
- Current local guidance and clinically reviewed scope/referral policy.
- Documented incident handling, evidence update monitoring, corrections, rollback, and reviewer ownership.
- Native simulator/device validation, signing credentials, and truthful App Store metadata.

These are prerequisites for public medical deployment, not pending implementation choices or approvals fabricated by this task. Source publication to GitHub is not an App Store or clinical deployment.
